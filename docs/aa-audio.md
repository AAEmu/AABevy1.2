# aa-audio: ArcheAge 1.2 sound

`crates/aa-audio` reads the sound of the original client (FSB5 banks, FMOD Designer `.fev` event files) and plays it in Bevy:
`Sound::event("sounds/x2skills:wild:fire_arrow_form")` on an entity, `Engine::play_2d(..)` for UI sounds, streamed music
with crossfades. Pure Rust, no C dependencies, nothing is decoded or read on the main thread, and an unattended run
(`--shot`, `--exit-after`, `AA_MUTE=1`) never opens an audio device.

```rust
app.add_plugins(aa_audio::AaAudioPlugin::default());
commands.spawn((Camera3d::default(), aa_audio::SpatialListener));
commands.spawn((Transform::from_xyz(3.0, 0.0, -5.0), aa_audio::Sound::event("sounds/x2skills:wild:fire_arrow_form")));
```

Wired into `aa-client` by `crates/aa-client/src/sound/` (`docs/aa-client-sound.md`): login and zone music, UI sounds, the sound
options, and with `aa-world` the placed ambience.

## FSB5 (`fsb5.rs`)

Header (0x3C bytes), the u64 sample headers with their chunks (channels, frequency, loop points, Vorbis CRC32 + seek table),
the name table, 16-byte aligned data. `Fsb5::parse(bytes)` reads only the headers; `subsound(i)` gives frequency, channels,
sample count, loop points, name, codec and the byte range of the data. A bank is read from the pak by range
(`Library::read_subsound`), never whole, so a 40 MB bank costs one subsound's bytes.

Codecs in the game: Vorbis (mode 15), MPEG (mode 11), one CELT (mode 12). The first two are implemented.

## Vorbis (`vorbis.rs`)

FMOD stores only the audio packets (`u16 length` + packet) and no headers. The three Vorbis headers are rebuilt:

* identification header: from channels and rate, block sizes 256 / 2048 (what FMOD's encoder always writes);
* comment header: empty (not needed to decode);
* setup header (codebooks, floors, residues, modes): looked up by the CRC32 stored in the sample's Vorbis chunk in
  `data/vorbis_setup.bin`.

`data/vorbis_setup.bin` holds the **23** setup headers that the game's banks use (the python-fsb5 table has 161 FMOD
headers; the 23 are those whose CRC32 occurs in the 6666 Vorbis banks, found with `--survey`). Source: the table
`lookup` in `fsb5/vorbis_headers.py` of [python-fsb5](https://github.com/HearthSim/python-fsb5) (HearthSim), MIT licence;
the notice is in `data/vorbis_setup.LICENSE` and the table is generated by `tools/make_setup_table.py`. The packets are decoded
by `lewton` (pure Rust). `vorbis::Stream` decodes block by block for streaming (music), `vorbis::decode` a whole subsound.

An unknown CRC32 gives `Error::UnknownSetup(crc)`; none of the 9186 subsounds does.

## MPEG (`mpeg.rs`)

The voice banks are MPEG-2 layer II, 24 kHz mono, 96 kbit/s. A subsound is a run of frames, zero padded to 16 bytes; the
frames are cut by their headers and decoded one by one with `symphonia-bundle-mp3` (layers 1 to 3). Output is mono i16.

## FEV (`fev.rs`)

Version `0x450000` (FMOD 4.44), all 69 files. The format is not documented anywhere I could find, so the grammar was
recovered from the game's own loader: `fmod_eventl.dll` decompiled in IDA (the `EventSystemI::load`, `EventGroupI::load`
and event loader functions, 26 MB of pseudo C in `data/extract/aa-audio/ida`, not in git), then checked on the data. The
full grammar is the module doc of `fev.rs` (`cargo doc -p aa-audio`); in short:

```
RIFF "FEV "  FMT (version)  LIST "PROJ": OBCT, PROP, LGCY (the body), EPRP (envelope points), STRR (strings), LANG
LGCY: banks, mixer categories (tree), event groups (tree of events), templates, sound definitions, reverbs, music chunks
```

`Fev::parse(bytes)` gives:

* `banks` (FSB names), `categories` (mixer tree, `Category::paths()`), `groups`, `events` (flat, each with `path()` =
  `group/sub/event`), `templates`, `sound_defs`, `reverbs`;
* `Event`: `volume`, `pitch` (raw, octaves = raw x 4), `pitch_random`, `volume_random`, `priority`, `max_playbacks`,
  `playback_behaviour`, `min_distance`, `max_distance`, `is_3d()` (mode bit 0x10), `rolloff()` (`Log`, `Linear`,
  `LinearSquare`, `Custom`), `one_shot()` (flags2 0x80000), `fade_in_ms`, `fade_out_ms`, `category` (mixer path such as
  `master/skill`), and `Body::Simple(instance)` or `Body::Complex { layers, parameters, props }`;
* `Layer` (control parameter, `Instance`s, `Envelope`s), `Instance` (sound definition, start and length on the parameter,
  `loops()`), `Parameter` (velocity, min, max, flags), `SoundDef` (template + `Wave`s: `Bank { weight, name, bank, index,
  length_ms }`, `Oscillator`, `Null`, `Programmer`), `Template` (Sequential / Random / Shuffle / Programmer, volume, pitch,
  randomization, fades).

Unknown fields are kept raw (`Event.raw`, `Instance.raw`, `Parameter.raw_44`, `Template.raw`) so nothing is lost.

### How an event plays (decided from the data)

| FMOD thing | Implemented as |
|---|---|
| Event volume, pitch, random pitch, random volume | volume linear; pitch ratio = 2^(raw x 4) with +-random; volume multiplier in [1 - random, 1] |
| 2D / 3D | mode bit 0x10 = 3D (placed, panned), otherwise 2D (centre); a 3D event without a position plays 2D |
| Min / max distance, rolloff | `Log` (inverse distance up to min, silent at max), `Linear`, `LinearSquare`, and `Custom` = the volume envelope on the `distance` parameter; gain is set by the engine (kira's own attenuation is off), so FMOD's curves are exact |
| Layers and parameters | an instance plays while its layer's parameter value lies in [start, start + length) (normalised over the parameter's range); layer volume envelopes (flag 0x8) apply; parameter `distance` / `camera_distance` / `(distance)` is the listener distance; `velocity` parameters advance by themselves (flag 0x8 wraps, `time_loop`); others start at their minimum and are set with `Sound::with_param` / `PlayOptions::params` |
| Sound definition | the template picks the wave: Sequential (next each trigger), Random, Shuffle (no repeat until all played), Programmer (not supported, silent); weights are the percent chances; template volume / pitch / randomization and fades apply |
| One shot / loop | `Instance::loops()` is `loop_word & 1 == 0` (1 = one shot, 0 = loop, 2 = loop to the end); looped sounds play until stopped; bank loop points are used when the bank has them |
| Max playbacks, behaviour | per event: 0 / 1 steal the oldest, 2 the newest, 3 the quietest, 4 refuse the new one, 5 refuse if it would be the quietest; overall limit `Settings::max_voices` (64), the highest priority number then the oldest is stopped first |
| Mixer category | the event's category path maps to a volume group (below) |

## Event paths

The same form is used everywhere the data names an event: `sounds.path` in `compact.sqlite3` (4868 rows, 4827 distinct paths;
the tables `sound_packs` / `sound_pack_items` map pack item names to those rows, and the Lua UI's `PlayUISound` / `PlayMusic`
take pack item names), the `Sound="Sounds/x2skills:wild:petget_hit"` attribute of particle emitters in
`game/libs/particles/*.xml`, and the `parameter` of `sound_pack` events in `.animevents` files
(`<event name="sound_pack" time="0.15" parameter="Sounds/x2monster_c:centipede:attack" .../>`):

```
sounds/<project>:<group>:<event>        sounds/x2skills:wild:fire_arrow_form
```

* `<project>` is the FMOD project: `game/sounds/<project>/<project>.fev`. 48 projects (`x2skills`, `x2monster_*`,
  `x2interface`, `x2music`, `x2eventsounds`, `x2voice_*` ...).
* `<group>` is the FMOD event group (nested groups join with `/`), `<event>` the event; together they are the FEV's path
  `group/event` (`Fev::event(path)`).
* Case does not matter (`Sounds/X2Skills:Wild:Fire_Arrow_Form`); `\` and `/` both work; the leading `sounds/` / `game/sounds/`
  can be left out.
* The group may repeat the project (`sounds/x2weapons:x2weapons:shield_flesh`); a pack of `project/group:event` with one colon
  (`sounds/x2skills/monster_skill:pino_effect.mon.mon_heal_hit`) and FMOD's own `project/group/event` (no colon) are accepted too.
* Voice projects (`x2voice_ai`, `_combat`, `_machinima`, `_quest_summary`, `_system`, `_tutorial`, `_vender`) have one FEV per
  language under `sounds/<project>/<lang>/` (`de`, `en_us`, `fr`) with the banks beside it, and a root copy.
  `Settings::language` selects the language folder (default `en_us`); a project or event missing from the language folder falls back to the root.

Resolution of the database paths (`sound --resolve data/extract/aa-audio/db_sound_paths.txt`, ~5 s):

| | |
|---|---|
| distinct paths | 4827 |
| resolved to an event | **4725** |
| project FEV not in the pak (fail quietly) | 41: `x2voice_prologue` 32, `x2voice_quest` 7, `x2voice_npc` 1, `x2minster_y` 1 |
| event not in the project | 59 (database errors, e.g. `sounds/x2ambience:world_object:gwe_harp`, `sounds/x2character:temp_ani:sk_bow_launch`; the match is strict, 2 would match by unique event name in another group) |
| not a path | 2 (`제작예정`, `제작중입니다`: "to be made") |

Every resolved event's waves were then checked against the banks (8124 waves, no missing bank, no subsound out of range,
all subsound names equal the wave names in the FEV).

Music: `sounds/x2music:screen:login_2013_07`, `login_cbt4_character`, `login_creator_oblivion`, ... (screen music, 30 groups
in `x2music`); the zone moods are the packs `soundmood_*` (17) whose items (`music_01` ...) map to `x2music` events via
`SoundPacks`.

### `SoundPacks` (database lookup)

```rust
let packs = aa_audio::SoundPacks::open(r"D:\aaemu-live\rs-game\Data\compact.sqlite3")?;   // read-only
packs.ui("login_stage_try_login");              // item of the `global` pack: what Lua PlayUISound / PlayMusic use
packs.path("window", "bag_show");               // any pack + item, case-insensitive
packs.sound(1234);                              // sounds.id (items, doodads, quests, FX) -> event path
```

It loads three small tables (`sounds`, `sound_packs`, `sound_pack_items`) once; the engine itself never touches the database.

## API

### Bevy

```rust
app.add_plugins(AaAudioPlugin::default());                         // Settings::auto(): muted when unattended
app.add_plugins(AaAudioPlugin::with(Settings { audible: true, ..default() }));
```

* `Sound` component: `Sound::event(path)`, `.with_volume(v)`, `.with_param("daylight", 1.0)`, `.despawn_when_done()`.
  3D events play at the entity's `GlobalTransform` and follow it; 2D events play centred. Removing the component or
  despawning the entity stops the sound with the event's fade out. A one-shot event removes the component (or despawns the
  entity) when it ends; changing `params` or `volume` of a playing `Sound` updates it in place, changing `event` restarts it.
* `SpatialListener` marker on the camera: its `GlobalTransform` is the listener (position and rotation, -Z forward).
* `Volumes` resource (`master`, `music`, `sfx`, `ambience`, `voice`, `ui`, each 0..1; the final volume of a sound is its
  event volume x its group x `master`). Changes apply live. Mixer category to group (`Category::of_mixer`):
  `music*` -> Music, `ambience*` and `underwater_only` -> Ambience, `*_voice` and `cutscene` -> Voice, `ui_button` -> UI,
  everything else (skills, monsters, footsteps, items, physics, weapons) -> SFX. `PlayOptions::category` overrides it.
* `Engine` resource (a cheap clone of a handle to the audio thread; every call only sends a message):

```rust
engine.play_2d("sounds/x2interface:interface:button_default");             // -> Voice
engine.play_at("sounds/x2skills:wild:fire_arrow_form", Vec3::new(1., 0., 4.));
engine.play_with(path, Some(pos), PlayOptions { volume: 0.5, params: vec![("gender".into(), 1.0)], ..default() });
engine.set_position(voice, pos);  engine.set_param(voice, "speed", 0.7);  engine.set_voice_volume(voice, 0.5);
engine.stop(voice, true /* with fade out */);  engine.stop_all();
engine.set_listener(pos, rot);  engine.set_volumes(volumes);                // the plugin does both
engine.play_music("sounds/x2music:screen:login_2013_07", Duration::from_millis(1500) /* in */, Duration::from_millis(1500) /* out */);
engine.stop_music(Duration::from_millis(500));
engine.stats();  engine.take_finished();  engine.wait_idle(timeout);        // tools and tests
```

* Unknown events, absent projects and undecodable sounds are ignored quietly (`Stats::unknown_events`,
  `Stats::decode_failures`; `tracing` at debug level).
* A 3D event further than its max distance is not started unless it loops (`Stats::culled`).
* `play_music`: the track streams from the bank (never decoded whole, never in the cache) and crossfades from the current one
  (fade out of the old, fade in of the new); asking for the playing track again does nothing. The track repeats when the
  event's instance loops (`login_2013_07` does: a 186 s track, loop word 0), between the bank's loop points or over the whole
  track (a loop rewinds the Vorbis stream and decodes forward to the loop start). Memory for a track is its compressed data
  (a few MB) plus a few decoded blocks.
* `Library` (`Library::global()`), `Fev`, `Fsb5`, `decode(..)` are public for tools: `Library::global().event(path)`
  gives an `EventRef`; `plan(..)` shows what a trigger would play (used by `--wav`).

### Muting

`audible_by_default()` is false with `--shot`, `--exit-after`, `--mute` or `AA_MUTE=1`; `--sound` overrides all of them.
`AaAudioPlugin::default()` uses it. A muted engine opens no device, reads nothing from the pak and decodes nothing, so a
screenshot run costs nothing and is silent. The audio device opens at the first sound that is played (not at startup);
a device error is kept in `Stats::device_error` and the engine goes on silent.

## Engine choice

[kira](https://crates.io/crates/kira) 0.12 (pure Rust, cpal backend; features: `cpal` only, no symphonia / mp3 / ogg decoders, we
decode ourselves):

* sub-tracks for the volume groups and spatial tracks for panning; per-sound gain, pitch (playback rate), fades and loop regions
  are first class;
* its `Decoder` trait lets the music stream from our own Vorbis block decoder, with crossfades, without decoding whole tracks;
* it runs its own mixer thread, so Bevy's frame rate never touches it.

`bevy_audio` (rodio) was not used: no custom streaming decoder hook for FMOD Vorbis, no per-sound gain curve updates from our
side, and its spatial model (distance attenuation) is not the FMOD rolloff the events carry. For the same reason kira's
distance attenuation is turned off and the engine computes the FMOD gain itself every 16 ms for each moving or 3D voice, which also
gives the exact `Custom` curves; kira only pans.

Threads: the audio thread (`aa-audio`: messages, voices, kira calls), the mixer thread (kira), and the decode jobs on
`aa_cry::workers::Workers` (the shared worker pool, priority below rendering assets). Pak reads happen on the workers
(banks by range) and the project FEVs are parsed on first use (a few ms each, cached).

## Performance and memory

* Decode: Vorbis 2.01 ms and MPEG 0.59 ms per second of audio. A typical skill event (4.05 s rendered, several layers)
  decodes in about 12 ms of worker time; a footstep or UI click in 1 to 3 ms. Time to first sound for a cold event is the
  FEV parse (first use of the project) plus pak read plus decode; a repeated event is a cache lookup.
* `SampleCache`: decoded sounds, stereo `f32` frames (8 bytes per frame, mono duplicated), LRU, bound `Settings::cache_bytes`
  = 128 MiB (about 6 minutes of 44.1 kHz audio). Concurrent requests for the same subsound share one decode.
* Parsed projects: all 69 FEVs together are a few MB; a project is loaded on its first event. Banks are opened lazily and
  only their headers are kept.
* Main thread: only `Engine` calls (a channel send) and two cheap systems in `PostUpdate`; no I/O, no decoding.
* Silent runs: zero (no device, no pak access).

## What is missing

* **CELT**: one subsound in the whole game (`x2weapons_sword_bank055.fsb:0`); a decoder would be a large port for one sound.
  It plays as silence (a decode failure is counted).
* FEV features read but not played: envelopes other than volume (pitch and low-pass envelopes), reverb, doppler, sound cones,
  speaker levels, spawn timers of templates (6 templates; one wave plays per trigger, repeats are not spawned), oscillator,
  silence and programmer waves (silent). Initial parameter values are the minimum (FMOD's default).
* Interactive music (cues, segments): none of the 69 files has music chunks (`Fev::music_bytes` is 0); the game's music is
  plain looping events.
* Events the database names but the data does not have: 59 absent events and 41 absent project FEVs (listed above); they play
  nothing. `x2voice_machinima` root FEV differs from the language ones (more banks), only the language one is used when
  `Settings::language` is set.
* Only music streams; every other sound, ambience loops included, is decoded whole into the cache (the longest are about a minute).
* No volume ducking between categories. The Lua `PlayUISound` / `PlayMusic` names are mapped by `aa-client` (`SoundPacks::ui`).
* What `aa-client` would still like (`docs/aa-client-sound.md`): a music-ended notification or query (it reads the event length from
  the FEV instead), `Engine::is_playing(voice)`, reverb.

## Browser (wasm32-unknown-unknown)

* There is no player thread: `Engine::start` builds the player in place and `Engine::pump` (run every frame by `AaAudioPlugin` in `Last`) does its work. `Workers` jobs run wherever `aa_cry::workers` runs them.
* kira has no streaming sounds in the browser (no threads), so music is decoded incrementally on the main thread: `buffered::buffered` makes a kira `Sound` that plays a queue of frames (silence on underrun, never blocks; volume, fade in, fade out on stop, linear resampling for the playback rate) and a `Feeder` that `Engine::pump` (every frame, the plugin does it) tops up with `vorbis::Stream` chunks to about 2 s queued, within a 2 ms budget shared by the tracks that still play. Starting a track only parses the headers. Loops decode the loop region again (rewind, decode and drop up to the loop start). Memory is about 2 s of frames per track instead of 60 MB; the app must keep calling `pump` (the plugin does).
* Output is cpal on WebAudio (kira enables cpal `wasm-bindgen` itself). Browsers keep the AudioContext suspended until a user gesture: the first sound is played (and the device opened) lazily, so the app should not play anything before the first click/key press, e.g. gate `Engine::play_*` on a user input event.
* The sound-pack database opens like aa-anim's (in-memory VFS, see its Browser note).
