  with `/addlabor`, `/spawn doodad`, `/move`, and item grants.
* Game server fields trace: `RUST_LOG=info,aaemu_game::net::fields=trace` (packet bodies).
* Record the full C->S / S->C stream from 3 s before the use to 15 s after it.
* Camera: side view (90 deg from the doodad) at 3 m, so the held tool and the cast pose are

* Sample the player's animation state every 0.25 s: clip name, skeleton time, held model
  path under `item_hand_r` / `item_hand_l`, and the item the client thinks it holds.
* Save screenshots at: bar up, cast 0.2 s, cast middle, cast end, loot/after.

## Packets to record and compare

* `CSStartSkill` 0x052: exact 13-byte body (skill, caster unit, target kind 4, doodad bc, flag 0).
* `SCSkillStarted` 0x0a1: skill id, target kind 4, cast ms, result.
* `SCSkillFired` 0x0a2, `SCSkillEnded`, `SCCastingStopped`/`SCSkillStopped` on a cancel.
* `SCDoodadPhaseChanged` 0x10f (group, time left, puzzle group, item template) and
  `SCDoodadRemoved` 0x10d.
* `SCItemTaskSuccess` 0x090: item, count, reason; note whether a loot bag (`SCLootBagData`)
  ever appears. The server grants `DoodadFuncLootItem` directly, so the client should not
  open the loot window; prove it on the original.
* `SCCharacterLaborPowerChanged` 0x045: amount, action, point, step.
* `SCErrorMsg` 0x10a for bag full / no labor / out of range.
* `SCDoodadSound` 0x156 if the func plays one.

## Pose and animation sampling

For each cast, sample at 0.0, 0.5, 1.0, 2.0, 4.0, 6.0 s after `SCSkillStarted`:

* the player's current clip name and whether it loops until the fire;
* the model under each hand bone (path), and whether the weapon is sheathed before the cast;
* the cast bar text and its fill (start/middle/end), and the action bar entries (icon, label,
  key) before the press;
* the doodad's model and size before and after the phase change.

## native.json (what the replay scaffold reads)

One object per case, written by this capture session:

```json
{
  "case": "ore_326",
  "skill": 11106,
  "doodad_template": 326,
  "target_kind": 4,
  "skill_started": {"cast_ms": 5000, "result": 0},
  "phase_changes": [425, 426],
  "removed": false,
  "item_tasks": [{"template_id": 123, "amount": 2, "grade": 0}],
  "labor": [-3],
  "errors": [],
  "frames": [{"t": 0.5, "clip": "...", "tool_r": "...", "cast_bar": "..."}]
}
```

`item_tasks` lists what `SCItemTaskSuccess` put into the bag, one entry per item added (a new
stack, or a stack add with a positive delta), decoded from the packet body like
`tools/gather_replay.py` `item_deliveries` does (aa-net `ItemTasks::read`); bag slots and item db
ids are left out because they differ from run to run, and the replay compares the entries as one
total per template id and grade. `skill_started.result` is the refusal code (0 = the cast
started) and is compared whenever it is listed.

Screenshots stay in `reference/gather/` (git-ignored); only the JSON and a short report are
tracked. The 2026-10-30 capture produced this file under `<capture-root>`; the results used by
the slice are in `capture-results.txt`.
