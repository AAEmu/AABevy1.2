nonzero movement, activity mask0x1, or an actor/forced input path.

do not reuse the mount passenger early return that swallows all intent.

key exit is not claimed by this audit.

close, or new Lua unbond API was identified. Do not add those as native claims.

Current integration points and smallest requirements
--------------------------------------------------
1. crates/aa-client/src/ingame/data.rs:430 doodad_phase_model ultimately uses
   model_file:522 ->prefab_model_file:575, which only searches object_Model.
   All three actual instrument prefabs are Brushes; they return no model.
   prepare.rs:182 consequently cannot build these doodads. Need full phase
   prefab/brush placement and a named-helper result, not first-mesh flattening.
   housing/prefab.rs:60 parts_of /:111 load and housing/render.rs:68 spawn_parts
   already contain brush transform parsing/render assembly reusable by root.
2. units.rs:173 Views::doodad_entity maps network object ID to RemoteDoodad
   root. units.rs:420..462 constructs that root; doodad_visual.rs:141 handles
   phase/model changes. Retain helpers through spawn/swap/removal, including
   root quaternion and scale. No DoodadWorldEntity symbol exists in current
   aa-client/aa-world sources checked here.
3. aa_cry LoadedModel.model (scene.rs:185) already exposes parsed nodes, and
   Model::world_transform(mesh.rs:263) composes helper ancestors. No new
   aa-cry API is inherently needed. scene.rs:399 only spawns render nodes and
   their ancestors, so an ordinary Children/CryNode search misses $bond0.
   Smallest presentation contract: doodad object -> current phase render
   root plus Option<full helper affine> for signed spot/name bond{spot}.
   If aa-world owns that resolver, it must cover prefab parts and raw CGF
   helper chains and distinguish not-ready from confirmed missing helper.
4. mount.rs:240 tracks only Player.spawn.unit.attached_to, and seat_world:126
   returns only a mount bone POSITION, later using mount yaw. Do not route
   doodad seats through it: full helper orientation and no mount clips/driver.
   Native393566c0's separate mount-conflict gate still belongs to root.
5. ingame/mod.rs:158..163 scheduling, player.rs:298 control_player and
   units.rs:645 move_units need seat ownership so floor snapping, gravity,
   mover updates and movement packets do not dislodge the bound actor.
   Consume exit intent before a seating input lock. anim.rs:398 locomotion,
   idle.rs:remote_idles and combat/buffs.rs:pose/remove_buff must arbitrate
   seat base pose versus performance/other Acting poses. Existing
   Animator::play_once_then(:210) can play the exact start/loop sequence;
   no missing CAF or mandatory new aa-anim public API was found.
6. Use DoodadBonds, not stale Player.spawn.unit.doodad_bond after SC139 or
   OwnUnitSnapshot. own()==None is known-free only if own_known()==true.
   DoodadBonds does not enforce the separate mount conflict itself.
   Queue Command::UnbondDoodad with captured selected char/actor/full bond.
   On matching UnbondRequested, local presentation may detach as native does;
   keep received history intact. A pending local detach must suppress immediate
   re-seating from the still-received bond. A local request is not SC13a.
   Teardown, object reuse, stale receipts, snapshot recovery and history-loss
   readiness remain the net contract, not synthetic local acknowledgements.
7. camera.rs:490 currently pivots from Mover.pos plus LocalMount lift. A seat
   mover/presentation offset needs to keep the camera/streaming focus aligned
   with the actual helper root. Exact native seated camera policy was not
   established; do not introduce a guessed camera height or zoom change.

Evidence status
---------------
Proven: packet route, spot-based helper name, optional '$', native world product,
scale removal, kind2->action19, graph clip sequence, native local detach,
movement/yaw unbond gate, all five catalog/template/phase rows and actual CGF
helper content. 13 isolated original-instruction cases passed. Build/visual FPS
is not measured, per research-only scope.

Still unverified: executing the native CGF/prefab-to-layout helper importer,

seated camera policy, live lane seat render/exit/ack behavior. These are not
grounds to guess transforms or animations. The smallest concrete implementation
